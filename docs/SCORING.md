# 타임어택 한국사 — 점수 및 랭킹 규칙 (score_version 2)

> 이 문서는 랭킹의 기준이 되는 점수 규칙입니다. 실제 계산 코드는 `functions/src/scoring.js`, 수치는 `functions/src/config.js`의 `SCORING`에 있습니다. 규칙을 바꾸면 이 문서와 코드를 함께 고치고 `version`을 올려 주세요.

---

## 1. 한 줄 요약

**한 판은 10문제, 문제당 최고 1,000점, 한 판 최고 10,000점입니다.**
**문제가 화면에 뜨는 순간부터 점수가 줄어듭니다.** 빨리 맞힐수록 점수가 높고, 늦게 맞히면 점수가 깎이며(최저 300점), **틀리거나 시간을 넘기면 0점**입니다.
시간은 **서버가 문제를 보여준 순간부터** 흐르고, 화면을 나가도 멈추지 않습니다.

> **v2 변경 (2026-11-21):** v1에는 지문 길이에 따라 처음 2.5~6초 동안 점수를 깎지 않는 "읽기 보호 시간"이 있었습니다. 그런데 문제가 뜬 뒤 점수가 멈춰 있다가 줄어들어서, 시간이 늦게 시작하는 것처럼 보였습니다. 그래서 없앴습니다. 지금은 네트워크 지연분 **0.5초**만 허용하고, 그 뒤로 바로 감점합니다.

## 2. 문제 한 개의 점수

| 결과 | 점수 |
|---|---|
| 정답 (0.5초 안에) | **1,000점** (만점) |
| 정답 (0.5초 ~ 20초) | 1,000 → 300점으로 계속 감소 |
| 오답 | **0점** |
| 시간 초과 (20초) | **0점** (오답과 같음) |

순서로 보면 항상 다음과 같습니다.

```
빠른 정답(1,000) > 느린 정답(300~999) > 오답 = 시간초과(0)
```

**가장 늦은 정답(300점)도 오답(0점)보다는 높습니다.** 그래서 "틀리면 가장 나쁘고, 늦으면 나쁘다"가 문제 하나 단위에서 항상 성립합니다.

### 2-1. 네트워크 허용 시간 (0.5초)

서버가 문제를 보낸 시각부터 재기 때문에, 문제가 휴대폰에 도착하는 시간(보통 0.1~0.3초)도 포함됩니다. 통신 상태 때문에 손해 보지 않도록, 처음 0.5초만 감점하지 않습니다. 사람이 문제를 읽고 누르는 데는 0.5초보다 오래 걸리니, 사실상 **문제가 뜨는 순간부터 감점**된다고 보면 됩니다.

### 2-2. 감점 곡선

```
x = (걸린 시간 − 0.5초) / (20초 − 0.5초)    ← 0 ~ 1 사이 값
점수 = 300 + 700 × (1 − x)^1.5              ← 소수점은 반올림
```

지수 1.5를 쓰기 때문에 **초반에는 빨리 깎이고, 뒤로 갈수록 천천히** 깎입니다. 그래서 잘하는 사람끼리는 1초 차이로도 순위가 갈리고, 늦게 푸는 사람도 300점 아래로는 떨어지지 않습니다.

| 정답까지 걸린 시간 | 점수 |
|---|---:|
| 0.5초 | 1000 |
| 1초 | 973 |
| 2초 | 921 |
| 3초 | 870 |
| 4초 | 820 |
| 5초 | 772 |
| 6초 | 726 |
| 7초 | 681 |
| 8초 | 638 |
| 10초 | 557 |
| 12초 | 484 |
| 14초 | 419 |
| 16초 | 365 |
| 18초 | 323 |
| 20초 | 300 |
| 20초 넘음 | 0 (시간 초과) |

## 3. 시간 측정 방식 (캡처해서 다른 곳에서 풀어오기 방지)

1. **기준은 서버 시각입니다.** 휴대폰이나 PC 시계는 쓰지 않습니다.
2. 서버가 문제를 처음 내려보낸 순간을 `served_at`으로 저장합니다. 이 값은 **딱 한 번만** 기록되고 다시 바뀌지 않습니다.
3. 걸린 시간은 `서버가 답을 받은 시각 − served_at`입니다.
4. 앱을 나가거나, 새로고침하거나, 다른 앱으로 가거나, 창을 닫아도 **시간은 계속 흐릅니다.** 다시 들어오면 남은 시간만큼만 풀 수 있고, 20초가 지났으면 그 문제는 시간 초과(0점)로 처리됩니다.
5. 다음 문제는 앞 문제의 답을 내야만 서버가 내려줍니다. 문제를 미리 받아 둘 수 없습니다.
6. 보기 순서는 출제할 때마다 서버가 섞습니다. "이 문제는 2번"처럼 위치를 외울 수 없습니다.
7. 제한시간이 끝났는지 판단할 때만 네트워크 지연을 감안해 1.5초를 더 기다려 줍니다. 이 1.5초 안에 들어온 정답은 300점입니다.
8. 화면의 "획득 가능 점수"는 문제가 뜨는 순간부터 위 곡선대로 줄어듭니다. 실제 점수는 서버가 계산하고, 화면 숫자는 그 예상치를 보여 줍니다.

**캡처한 뒤 검색해서 풀어오면 어떻게 되나요?** 캡처 → 다른 앱으로 이동 → 검색 → 돌아오기까지 보통 15초 이상 걸립니다. 이렇게 풀면 문제당 300~450점, 한 판에 약 3,000~4,500점이 됩니다. 정상적으로 잘 푸는 사람(7,000점 이상)보다 훨씬 낮기 때문에 **랭킹 상위에 오를 수 없습니다.**

## 4. 한 판(10문제) 구성: 공정성 장치

판마다 문제가 무작위로 나오므로, 판마다 어려운 정도가 비슷하도록 다음 규칙으로 문제를 고릅니다.

- **시대 배분 (10문제):** 선사·고조선 1, 삼국·남북국 2, 고려 1, 조선 전기 1, 조선 후기 1, 근대 1, 일제강점기 2, 현대 1
- **난이도 배분:** 하 3, 중 5, 상 2 (해당 시대에 그 난이도 문제가 없으면 다른 난이도로 채움)
- **같은 지식을 묻는 변형 문제(`fact_group_id`가 같은 문제)는 한 판에 1개만** 나옵니다.
- **최근 14일 안에 본 문제는 되도록 빼고** 고릅니다. (백오피스 설정에서 바꿀 수 있음)
- 위 조건으로 고른 10문제의 **출제 순서는 섞습니다.**

`npm run simulate` 를 실행하면 이 표를 다시 계산할 수 있습니다.

## 6. 이렇게 맞춘 이유 (밸런스 설계)

| 원칙 | 어떻게 맞췄나 |
|---|---|
| 틀리면 가장 나쁘다 | 오답 0점 < 가장 늦은 정답 300점. 오답 1개는 만점 대비 −1,000점이고, 가장 늦게 맞혀도 −700점이라 **틀리는 쪽이 항상 손해가 더 큽니다.** |
| 아무렇게나 찍으면 손해 | 보기 4개 중 아무거나 찍으면 기대 점수는 250점(1,000 × 1/4)입니다. 답을 알면 20초 끝까지 생각해서 맞혀도 300점이라 **찍는 것보다 생각하는 게 낫습니다.** (보기를 2개로 줄였다면 찍는 것도 합리적인 선택입니다.) |
| 빠를수록 좋다 | 문제가 뜨는 순간부터 감점하고, 처음 몇 초 동안 가장 크게 깎이도록(지수 1.5) 만들어서, 상위권은 1초 차이로도 순위가 갈립니다. |
| 정확도도 중요하다 | "2개 틀리고 평균 2초"(7,368) < "다 맞히고 평균 5초"(7,720). 즉, **2문제 틀린 것은 매 문제 3초씩 더 쓴 것보다 손해**입니다. 속도와 정확도가 한쪽으로 쏠리지 않습니다. |
| 시간이 바로 흐르는 느낌 | v1의 읽기 보호 시간(점수가 처음 몇 초 멈춰 있음)을 없앴습니다. 지문이 긴 문제는 조금 불리하지만, 한 판의 시대·난이도 배분이 같아서 판끼리 차이는 작습니다. |
| 운의 영향 줄이기 | 판마다 시대와 난이도를 고정 비율로 맞추고, 같은 지식을 묻는 문제는 한 판에 1개만 나옵니다. |
| 다른 곳에서 풀어오기 막기 | 서버 시각 기준, 한 번 시작된 시간은 멈추지 않음, 20초 제한, 보기 순서 섞기. |

## 7. 주간 랭킹

- **기간:** 한국 시간(KST) 기준 매주 월요일 00:00 ~ 일요일 23:59:59. 끝까지 푼 시각이 속한 주에 들어갑니다.
- **사람마다 그 주의 가장 높은 점수 1개만** 순위에 들어갑니다. (여러 번 도전 가능)
- **동점일 때 순서:** ① 점수가 높은 순 → ② 10문제 총 소요시간이 짧은 순 → ③ 먼저 기록한 순
  - 점수가 같으면 총 소요시간으로 순위가 정해집니다.
- 끝까지 풀지 않은 판(중간 포기, 30분 이상 방치)은 순위에 넣지 않습니다. 새 판을 시작하면 진행 중이던 판은 포기 처리되고, 남은 문제는 시간 초과로 기록됩니다.
- 하루 도전 횟수 제한은 백오피스에서 설정할 수 있습니다. (기본값: 제한 없음)

## 8. 부정행위 감지 (백오피스)

| 신호 | 기준 | 처리 |
|---|---|---|
| 너무 빠른 정답 | 0.7초 안에 맞힘 (사람이 읽고 누르기 어려운 속도, 봇 의심) | 그 문항에 표시 |
| 의심 판 | 한 판에 너무 빠른 정답이 3개 이상 | 판에 `flagged` 표시. 관리자가 확인한 뒤 **실격** 처리 가능 |
| 화면 이탈 | 문제를 푸는 동안 창 포커스를 잃거나 화면이 가려짐 | 기록만 남김 (점수에는 영향 없음, 시간은 원래 계속 흐름) |

실격된 판과 차단된 사용자는 랭킹에서 빠집니다.

## 9. 화면 캡처 방지 (보조 수단)

웹 브라우저에서는 캡처를 **완전히 막을 수 없습니다.** 그래서 핵심 방어는 3장의 시간 규칙이고, 아래 기능은 보조 수단입니다.

- 문제를 푸는 동안 창 포커스를 잃거나, 탭을 바꾸거나, 화면이 가려지면 **문제를 검은 화면으로 가립니다.** (Windows의 Win+Shift+S 캡처 도구, 앱 전환 등에 해당)
- PrintScreen 키를 누르면 즉시 화면을 가리고 클립보드를 비웁니다.
- Mac의 캡처 단축키(⌘+Shift+3/4/5) 조합이 눌리기 시작하면 화면을 가립니다.
- 텍스트 선택·복사, 우클릭, 드래그, 인쇄를 막습니다. 인쇄하면 빈 화면이 나옵니다.
- 문제 영역에 닉네임 워터마크를 넣어서, 캡처가 밖으로 퍼지면 누가 찍었는지 알 수 있게 합니다.
- **네이티브 앱에서는 OS 기능으로 막을 수 있습니다.** Android는 `FLAG_SECURE`를 쓰면 캡처와 녹화가 검은 화면이 됩니다. iOS는 보안 텍스트 필드 레이어 기법으로 화면을 가리고, `UIScreen.capturedDidChange`와 `userDidTakeScreenshotNotification`으로 녹화나 캡처를 감지합니다. 앱으로 만들 때 꼭 적용하세요.

## 10. 앞으로 보정할 것 (실제 데이터가 쌓인 뒤)

- **긴 지문 보정(필요하면):** 지문이 긴 문항의 정답 소요시간이 눈에 띄게 길면(백오피스 문항 상세 → "정답 소요시간 분포"), 그 문항을 짧게 다듬거나 난이도를 올려 공정성을 맞춥니다.
- **난이도 재조정:** 백오피스에서 실제 정답률로 추천 난이도를 계산합니다. 정답률 80% 이상은 하, 50% 이상은 중, 그 미만은 상입니다. 일괄 적용 버튼도 있습니다. 난이도가 정확해질수록 4장의 난이도 배분이 더 공정해집니다.
- 규칙을 바꾸면 `SCORING.version`을 올리세요. 그 주가 끝난 뒤(월요일 00:00)에 바꾸는 것을 권장합니다. 한 주 안에서 서로 다른 버전 점수가 섞이지 않게 하기 위해서입니다.
